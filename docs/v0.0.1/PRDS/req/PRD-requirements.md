## 1. 概述

Studyboard 是一款以自由探索为核心哲学的知识学习工具。它提供一块无限大的知识画布，用户通过与 AI 对话学习知识，知识点自动成为画布上的节点并基于相关性建立连接，形成个人知识图谱。产品强调理解而非记忆、探索而非目标驱动、主动建构而非被动接受。

## 2. 问题陈述

当前学习工具存在以下核心痛点：

| 痛点 | 现状 | Studyboard 的回应 |
|------|------|-------------------|
| 知识碎片化 | 笔记散落各处，无法形成体系 | 无限画布 + 自动连接，知识自然成网 |
| 被动学习 | 做题、背诵，用户处于被检验地位 | 辩论与设计，用户是主动建构者 |
| 动力衰减 | 目标驱动的学习难以持续 | 自由探索，学习本身即奖励 |
| 信息茧房 | 算法只推荐相似内容 | 破茧推荐，主动引入无关领域 |
| 理解浅层化 | 知道≠理解，缺乏深度验证 | 费曼式讲解 + 苏格拉底式追问 |
| 结构僵化 | 课程大纲是预设的线性路径 | 图谱结构自由生长，每个人不同 |

## 3. 产品哲学与设计原则

| 编号 | 原则 | 定义 | 设计约束 |
|------|------|------|----------|
| DP-1 | 内在动机 | 学习不预设目的，好奇心即动力 | 不设打卡、积分、等级等外部激励 |
| DP-2 | 理解优先 | 不强调记忆，强调理解知识间的联系 | 无记忆卡片、无重复背诵机制 |
| DP-3 | 自由探索 | 鼓励"跑题"，跑题本身就是学习 | 不强制线性路径，允许任意方向延伸 |
| DP-4 | 主动建构 | 通过辩论和设计验证理解 | 不做选择题/填空题，用户是创造者非应答者 |
| DP-5 | 连接即理解 | 知识的价值在于连接 | 孤立节点应被引导建立关联 |

## 4. 目标用户画像

### Persona A：自由探索者

- 对世界保持好奇，享受学习过程本身
- 场景：晚上睡前随便看看"黑洞是怎么回事"，从广义相对论聊到时间膨胀，又跑到哲学上的时间观
- 期望：不被打断、不被规划、自由蔓延

### Persona B：跨域连接者

- 不满足于单一领域，喜欢发现知识间的隐藏联系
- 场景：学编程时突然想到"这跟生态学里的共生关系好像"，想把这两个点连起来
- 期望：画布上能看到不同领域知识的交汇

### Persona C：深度理解者

- 不满足于"知道"，追求"真正搞懂"
- 场景：学了 Transformer 但感觉似懂非懂，想通过给别人讲一遍来检验自己
- 期望：有人（AI）认真听我讲，提出我没想到角度的问题

## 5. 功能需求

### 5.1 模块 A：无限知识画布

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-001 | 画布支持无限平移 | P0 | Given 画布已加载，When 用户拖拽空白区域，Then 画布跟随移动，无边界限制 |
| FR-002 | 画布支持缩放 | P0 | Given 画布已加载，When 用户滚轮/双指缩放，Then 画布平滑缩放（0.1x ~ 3x） |
| FR-003 | 节点可自由拖拽定位 | P0 | Given 画布上有节点，When 用户拖拽节点，Then 节点跟随移动并保存新位置 |
| FR-004 | 节点间连线表达关联 | P0 | Given 两个节点存在，When 用户从节点 A 边缘拖向节点 B，Then 创建一条连线 |
| FR-005 | 连线可手动删除 | P0 | Given 存在连线，When 用户选中连线并按 Delete，Then 连线被删除 |
| FR-006 | 多层级缩放视图 | P1 | Given 画布有多层级节点，When 缩放至 <0.3x，Then 仅显示领域级节点；<0.6x 显示主题级；<1.0x 显示子主题级；>=1.0x 全部显示 |
| FR-007 | 双击空白处手动创建节点 | P0 | Given 画布已加载，When 用户双击空白区域，Then 在该位置创建新节点并进入编辑状态 |

### 5.2 模块 B：知识节点系统

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-010 | 支持 5 种节点类型 | P0 | Given 系统运行，When 创建节点，Then 可选择 concept/theme/material/understanding/question 类型，各类型有视觉区分 |
| FR-011 | 节点包含富文本内容 | P0 | Given 节点已创建，When 用户编辑节点，Then 支持 Markdown 格式内容编辑 |
| FR-012 | 节点可编辑标题和内容 | P0 | Given 节点存在，When 用户双击节点，Then 打开详情面板可编辑 |
| FR-013 | 节点可删除 | P0 | Given 节点存在，When 用户执行删除操作，Then 节点及其所有关联连线被删除 |
| FR-014 | 节点附带对话记录 | P1 | Given 节点由对话产生，When 用户查看节点详情，Then 可看到产生该节点的对话上下文 |
| FR-015 | AI 辅助节点分化 | P1 | Given 一个包含多个知识点的节点，When 用户指示 AI 拆分，Then 原节点被拆为多个子节点，连线重新分配 |
| FR-016 | 节点合并 | P2 | Given 两个相关节点，When 用户指示合并，Then 两节点合为一个，内容整合 |
| FR-017 | 材料节点支持链接导入 | P1 | Given 用户提供一个 URL，When 导入为材料节点，Then 创建 material 类型节点并记录来源链接 |

### 5.3 模块 C：多层级结构

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-020 | 支持动态多层级 | P1 | Given 知识图谱存在，When 节点聚集，Then 系统可自动生成主题层（领域→主题→子主题→知识点→子点） |
| FR-021 | 层级可动态插入 | P1 | Given 已有两层结构，When AI 识别到需要中间层，Then 可在任意两层间插入新层级 |
| FR-022 | 允许跨层级连接 | P1 | Given 不同层级的节点，When 建立连线，Then 不受层级限制，任意两节点可直连 |
| FR-023 | 主题自动生成 | P1 | Given 3+ 个语义相关的知识点节点，When 触发主题归纳，Then 自动生成主题节点并将相关节点收纳其下 |

### 5.4 模块 D：AI 对话学习

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-030 | 学习模式对话 | P0 | Given 用户打开对话面板选择"学习"模式，When 用户提问，Then AI 以友善讲解者身份流式回复 |
| FR-031 | 费曼模式对话 | P0 | Given 用户选择"费曼"模式，When 用户阐述理解，Then AI 以求知者姿态追问，不否定、不评判 |
| FR-032 | 对话驱动节点生成 | P0 | Given 一段学习对话结束，When 系统解析对话，Then 自动提取知识点生成画布节点 |
| FR-033 | 追问补充或分裂节点 | P0 | Given 用户在已有节点上下文中追问，When 对话结束，Then 系统判断是补充原节点还是生成新节点 |
| FR-034 | 对话中推荐材料 | P1 | Given 对话进行中，When AI 认为有辅助材料，Then 推荐文章/视频/PDF 链接，用户可一键加入画布 |
| FR-035 | 自然语言操作图谱 | P1 | Given 用户在对话中说"把这个节点拆成三个"，When AI 识别意图，Then 执行对应图谱操作 |
| FR-036 | 流式输出 | P0 | Given 用户发送消息，When AI 回复，Then 逐 token 流式显示，首 token 延迟 < 3s |
| FR-037 | 对话面板可收起 | P0 | Given 对话面板打开，When 用户点击收起，Then 面板隐藏，画布占满全屏 |

### 5.5 模块 E：双模推荐系统

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-040 | 相关性推荐 | P1 | Given 用户正在学习某节点，When 触发推荐，Then 显示 3-5 个语义相关但未学过的延伸方向 |
| FR-041 | 破茧推荐 | P2 | Given 用户知识图谱已有一定规模，When 触发破茧推荐，Then 显示 2-3 个与已有知识完全无关的有趣领域 |
| FR-042 | 推荐低侵入性 | P2 | Given 推荐产生，When 展示给用户，Then 不弹窗不打断，仅在画布"漫游区"或对话末尾自然呈现 |
| FR-043 | 用户主动触发推荐 | P1 | Given 用户想探索，When 点击"给我个惊喜"，Then 立即生成一条破茧推荐 |

### 5.6 模块 F：领域图谱模式

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-050 | 生成未点亮领域图谱 | P1 | Given 用户输入领域名称（如"机器学习"），When 确认生成，Then 画布上出现该领域的多层级灰色/虚线节点图谱 |
| FR-051 | 节点点亮机制 | P1 | Given 存在未点亮节点，When 用户通过对话学习了匹配的知识，Then 对应节点自动变为点亮状态 |
| FR-052 | 允许图谱外自由扩展 | P1 | Given 领域图谱已生成，When 用户学习图谱外的知识，Then 新节点正常生成在图谱之外 |
| FR-053 | 未点亮节点悬停预览 | P2 | Given 存在未点亮节点，When 用户悬停，Then 显示一句话描述该节点内容 |
| FR-054 | 与自由探索模式共存 | P1 | Given 画布上已有自由探索的节点，When 生成领域图谱，Then 两者共存互不干扰 |

### 5.7 模块 G：理解验证（辩论与设计）

| ID | 需求 | 优先级 | 验收标准 |
|----|------|--------|----------|
| FR-060 | 辩论模式 | P2 | Given 用户选择"辩论"模式，When 用户提出观点，Then AI 以聪明怀疑者身份提出有深度的质疑 |
| FR-061 | 设计模式 | P2 | Given 用户选择"设计"模式，When 用户描述设计目标，Then AI 引导用户做决策并追问论证 |
| FR-062 | 不判对错 | P2 | Given 辩论/设计对话中，When AI 回应，Then 绝不给出"对/错"判定，只推动思考深入 |

## 6. 非功能需求

| ID | 需求 | 指标 | 优先级 |
|----|------|------|--------|
| NFR-001 | 画布渲染流畅度 | 节点数 < 500 时保持 60fps | P0 |
| NFR-002 | AI 首 token 响应 | < 3 秒 | P0 |
| NFR-003 | 数据持久化 | 刷新/关闭浏览器后数据不丢失 | P0 |
| NFR-004 | 浏览器兼容 | Chrome 90+, Firefox 90+, Safari 15+, Edge 90+ | P0 |
| NFR-005 | 首屏加载时间 | < 3 秒（生产环境） | P1 |
| NFR-006 | 大量节点性能 | 1000 节点时画布操作不卡顿（>30fps） | P2 |

## 7. 核心用户旅程

```
用户打开 Studyboard → 看到无限画布
    │
    ├── 路径 A：自由探索
    │   打开对话 → 提问 → AI 讲解 → 节点自动生成 → 追问 → 节点丰富/分裂
    │   → AI 推荐延伸 → 继续探索 → 画布持续生长
    │
    ├── 路径 B：费曼验证
    │   选择已有节点 → 进入费曼模式 → 向 AI 讲解理解 → AI 追问 → 深化理解
    │
    ├── 路径 C：领域入门
    │   输入领域名 → 生成未点亮图谱 → 选择感兴趣的节点 → 对话学习 → 点亮
    │
    └── 路径 D：辩论/设计
        选择节点 → 进入辩论/设计模式 → 论证/创造 → 深化理解
```

## 9. 约束与假设

### 约束

- MVP 阶段仅开发 Web 端
- AI 能力依赖千问 API（qwen-plus-3.7），通过 OpenAI 兼容接口调用
- 数据存储在浏览器本地（IndexedDB），无后端数据库
- 单用户模式，无协作功能

### 假设

- 用户有稳定的网络连接（AI 对话依赖网络）
- 用户知识图谱规模在 MVP 阶段不超过 1000 节点
- 千问 API 能稳定提供流式输出和结构化输出能力
