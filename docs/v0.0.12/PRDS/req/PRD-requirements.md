## 概述

在主对话面板中支持将一段连续对话标记为"分段"，分段可命名（手动或AI自动）、可折叠、可一键全选并生成节点，帮助用户组织长对话、聚焦主题。

---

## 问题陈述

| # | 痛点 | 影响 |
|---|------|------|
| 1 | 长对话难以定位特定主题讨论 | 信息过载，无法快速回顾 |
| 2 | 想对某段对话生成节点时需逐条Shift选择 | 操作繁琐 |
| 3 | 对话缺乏结构化组织 | 知识碎片化 |

---

## 设计原则

- **DP-1**：轻量标记 — 不打断对话流，通过消息侧边按钮标记起止
- **DP-2**：即时折叠 — 标记完成后立即可折叠，减少视觉噪音
- **DP-3**：智能命名 — AI自动提取主题，减少手动输入
- **DP-4**：批量操作 — 一键全选段内消息，复用已有"生成节点"能力

---

## 功能需求

### FR-001：标记分段起始 [P0]

**Given** 用户在对话面板中
**When** 用户点击某条消息的「标记为起始」按钮
**Then** 该消息被标记为当前分段的起始点，视觉上高亮显示

验收标准：
- [ ] 每条消息悬停时显示「标记起始」图标按钮
- [ ] 点击后该消息左侧出现起始标记线
- [ ] 同一时间只能有一个"待结束"的起始标记

### FR-002：标记分段结束并命名 [P0]

**Given** 已标记起始消息
**When** 用户点击后续某条消息的「标记为结束」按钮
**Then** 弹出命名输入框，用户输入名称后确认，该段对话被创建为一个分段

验收标准：
- [ ] 起始标记后，后续消息显示「标记结束」按钮
- [ ] 点击后弹出命名弹窗（含输入框 + 确认/取消）
- [ ] 确认后分段创建成功，起止消息间的所有消息归入该分段
- [ ] 分段数据持久化（随对话保存）

### FR-003：AI 自动命名 [P0]

**Given** 用户标记了一段对话的起止
**When** 用户点击「自动命名」按钮
**Then** AI 基于该段对话内容生成一个简短主题名

验收标准：
- [ ] 命名弹窗中提供「AI 命名」按钮
- [ ] 点击后调用 AI 接口，返回 ≤10 字的主题名
- [ ] 生成结果填入输入框，用户可修改后确认
- [ ] 加载状态有 spinner 提示

### FR-004：分段折叠/展开 [P0]

**Given** 已创建的分段
**When** 用户点击分段标题栏
**Then** 该段对话折叠为一行（显示主题名 + 消息数），再次点击展开

验收标准：
- [ ] 折叠后显示：主题名 + 消息条数 + 展开按钮
- [ ] 展开后恢复显示所有消息
- [ ] 折叠状态持久化
- [ ] 折叠时该段占位高度 ≤ 40px

### FR-005：一键全选段内消息 [P0]

**Given** 一个已创建的分段
**When** 用户点击分段标题栏的「全选」按钮
**Then** 该段所有消息被选中（进入多选模式）

验收标准：
- [ ] 分段标题栏提供全选图标按钮
- [ ] 点击后段内所有消息进入 selectedMessages 集合
- [ ] 选中后可直接使用已有的「生成节点」功能

### FR-006：分段内生成节点 [P0]

**Given** 一个分段被全选
**When** 用户点击「生成节点」
**Then** 复用已有的 parseConversationToGraph 逻辑，仅对该段消息生成节点

验收标准：
- [ ] 分段标题栏提供「生成节点」按钮（无需先全选）
- [ ] 点击后直接对该段消息调用归纳逻辑
- [ ] 生成过程中按钮显示 loading

### FR-007：分段管理 [P1]

**Given** 已创建的多个分段
**When** 用户需要编辑或删除分段
**Then** 支持重命名和删除分段

验收标准：
- [ ] 分段标题栏悬停显示编辑/删除按钮
- [ ] 重命名弹出输入框
- [ ] 删除后消息恢复为普通消息（不删除消息本身）

## 约束与假设

- 分段信息存储在对话的 metadata 中（与消息列表同级）
- 分段不嵌套（一个消息只能属于一个分段）
- AI 命名复用已有的 `/api/chat` 接口（单轮 prompt）
