## 概述

让知识节点在画布上支持两种呈现形态（圆点 / 可展开卡片），并让 AI 能够理解用户上传的文件与视频内容，实现"所传即所懂"的多模态知识管理。

---

## 问题陈述

| # | 痛点 | 影响 |
|---|------|------|
| 1 | 节点只有圆点形态，内容/笔记/白板需点开详情才能看 | 画布信息密度低，回顾时需频繁切换 |
| 2 | 上传的 PDF/Word/图片/视频，AI 无法理解其内容 | 多模态材料沦为"死"节点，无法参与对话与归纳 |
| 3 | 视频内容无法被提取利用 | 视频类学习材料价值无法释放 |

---

## 设计原则

- **DP-1**：形态可切换 — 圆点与卡片两种形态一键切换，全局或单节点可控
- **DP-2**：卡片即摘要 — 卡片内直接展示内容摘要、笔记数、白板缩略图，无需点开
- **DP-3**：多模态优先原生 — 优先用模型原生多模态能力（qwen-vl/omni）理解图片/视频
- **DP-4**：降级转换兜底 — 模型不支持时，先转换（视频抽帧/文件转文本）再理解
- **DP-5**：理解结果可沉淀 — 多模态理解产出摘要，存入节点 content/summary，参与后续对话与归纳

## 功能需求

### FR-001：节点卡片形态 [P0]

**Given** 画布上存在节点
**When** 用户切换展示形态（全局开关或单节点双击卡片按钮）
**Then** 节点在圆点与卡片两种形态间切换

验收标准：
- [ ] 提供全局形态切换开关（工具栏）
- [ ] 卡片形态展示：标题、内容摘要（前 N 字）、笔记数、类型标签
- [ ] 卡片形态对有白板的节点展示白板缩略图
- [ ] 圆点形态保持现有 Obsidian 风格渲染
- [ ] 形态切换有平滑过渡动画

### FR-002：卡片内快捷操作 [P1]

**Given** 节点以卡片形态展示
**When** 用户悬停/点击卡片上的操作区
**Then** 可直接展开详情、查看笔记、打开白板

验收标准：
- [ ] 卡片提供"展开详情"按钮
- [ ] 卡片显示笔记条数并可点击查看
- [ ] 卡片白板缩略图可点击打开白板

### FR-003：图片多模态理解 [P0]

**Given** 用户上传一张图片作为节点
**When** 用户触发"理解内容"
**Then** AI 用原生视觉能力（qwen-vl）分析图片并产出摘要

验收标准：
- [ ] 图片以 base64/URL 形式传给视觉模型
- [ ] 产出摘要存入节点 summary
- [ ] 摘要可用于后续对话上下文

### FR-004：文件（PDF/Word）理解 [P0]

**Given** 用户上传 PDF/Word 节点
**When** 用户触发"理解内容"
**Then** 提取文本后交给模型理解，产出摘要

验收标准：
- [ ] 复用现有 PDF/Word 文本提取
- [ ] 提取文本送模型生成摘要
- [ ] 摘要存入节点 summary

### FR-005：视频理解 [P1]

**Given** 用户上传视频节点
**When** 用户触发"理解内容"
**Then** 优先用视频模型（qwen-omni/vl）理解；不支持则抽帧转图片再理解

验收标准：
- [ ] 尝试原生视频模型理解
- [ ] 降级路径：抽帧 → 多图送视觉模型
- [ ] 产出摘要存入节点 summary

### FR-006：理解结果参与对话 [P0]

**Given** 节点已有多模态摘要
**When** 用户就该节点与 AI 对话
**Then** 摘要作为上下文注入 system prompt

验收标准：
- [ ] 对话上下文包含节点 summary
- [ ] 归纳/推荐可利用 summary

## 约束与假设

- 视觉模型使用 `qwen-vl-plus` / `qwen-omni`，通过 DashScope OpenAI 兼容接口传 image_url/video
- 视频抽帧在前端用 `<canvas>` 实现，无需后端 ffmpeg
- 卡片形态与圆点形态共用同一节点数据，仅渲染层不同
